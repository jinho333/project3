## 2. 집에서 시작하는 순서

1. 브랜치 받기
   ```
   git fetch origin
   git switch ft/admin-map
   ```
2. `src/main/resources/application.yaml` 준비 (git에서 제외된 파일이라 직접 넣어야 함)
   - 구글 챗에 있는 파일을 `src/main/resources/`에 넣기
   - **팀 DB는 학교 네트워크 안의 주소라 집에서는 접속이 안 됩니다.** 지도 화면은 DB 없이 동작합니다.
   - 카카오 JavaScript 키를 아래 형식으로 추가 (키 값은 대화나 저장소에 올리지 않기)
     ```yaml
     kakao:
       js:
         key: 여기에_JavaScript_키
     ```
3. 실행 후 확인
   ```
   ./gradlew bootRun
   ```
   `http://localhost:8080/admin` 에서 울산 지도와 오른쪽 확대/축소 버튼이 보이면 정상

## 3. 카카오 설정 (이미 해 둔 것, 집에서 다른 PC라도 그대로 유효)

- JavaScript 키 발급 완료 (기본 JS 키)
- JavaScript SDK 도메인에 `http://localhost:8080`, `http://localhost:8081` 등록
- **카카오맵 사용 설정 ON** (이게 꺼져 있으면 키와 도메인이 맞아도 403이 나서 지도가 안 뜸)

지도가 안 뜰 때 점검:

| 증상 | 확인 |
|---|---|
| "카카오 지도를 불러오지 못했습니다" | `application.yaml`의 `kakao.js.key`, 서버 재시작, 강력 새로고침(Ctrl+F5) |
| SDK 요청이 401 | 키가 틀렸거나 등록하지 않은 주소(포트)로 접속 |
| SDK 요청이 403 | 카카오맵 사용 설정이 꺼져 있음 |
| 포트가 다름 | 등록한 주소와 접속 주소(`localhost` 대 `127.0.0.1`, 포트)가 같은지 |

## 4. 다음 할 일: B단계 계획

목표: 서버 API를 통해 노선 선을 받아 지도에 그리고, **없는 노선이면 화면에 안내**한다.

```
[노선 버튼 클릭] → 지도 JS → 서버 API → 노선 데이터 서비스 → (지금) GeoJSON 파일
                       200 + GeoJSON → 선을 그림
                       404          → "없는 노선" 안내
```

만들 것:

| 파일 | 역할 |
|---|---|
| `AdminApiController.java` (새) | `GET /admin/api/routes/{노선번호}/geometry`, 있으면 200, 없으면 404, 형식이 이상하면 400 |
| `RouteGeometryService.java` (새) | 노선번호로 GeoJSON을 찾음 (지금은 파일, 나중에 DB로 교체하는 지점) |
| `dashboard.html` | 임시 노선 버튼 (741 / 1144 / 9999), 4단계에서 실제 목록으로 교체 |
| `dashboard_map.js` | 불러오기, 선 그리기, 기존 선 지우기, 오류 안내 |
| `dashboard.css` | 버튼과 메시지 모양 |

오류 처리:

| 상황 | 서버 | 화면 |
|---|---|---|
| 있는 노선(741) | 200 | 두 방향 선을 같은 색으로 그림 |
| 없는 노선 / 데이터 없음 (1144, 9999) | 404 | "○○번 노선은 지도에 표시할 수 없습니다 (없는 노선이거나 데이터가 없습니다)" |
| 이상한 입력(`../` 등) | 400 | "잘못된 노선번호입니다" |
| 서버 오류, 네트워크 실패 | 500 / 요청 실패 | "노선을 불러오지 못했습니다. 잠시 후 다시 시도하세요" |

- 실패해도 **직전에 그려 둔 노선은 유지**
- 노선번호로 서버 파일을 찾으므로 **허용 문자를 숫자, 영문, 한글, 최대 10자로 제한** (다른 파일을 읽는 사고 방지)

진행 순서:
1. 서버 API와 서비스를 만들고, 주소를 직접 호출해서 741은 200, 1144/9999는 404, `../`는 400인지 확인
2. 지도 JS에서 불러와 선 그리기, 브라우저에서 741 확인
3. 오류 안내 표시, 1144와 9999 눌러서 확인
4. 노선을 번갈아 눌러도 선이 쌓이지 않는지 확인

아직 정하지 않은 것 (제안값):

| 결정 | 제안 |
|---|---|
| 노선 선택 방식 | 임시 버튼 3개 (번호 입력칸은 선택) |
| GeoJSON 파일 위치 | 지금 `static/data/routes/`는 주소로 직접 열 수 있음. API로만 받게 하려면 `static` 밖으로 이동 |
| 안내 문구 | 위 문구 |
| 실패 시 직전 노선 | 유지 |

## 6. 지도 동작 규칙 (팀 확정)

- 모드 2개: `top5`, `single`
- 처음 들어오면 **Top5 모드**: 혼잡 상위 5개 노선을 흰색 테두리와 등급 색으로 표시, 순위 배지(1~5)
- Top5 모드에서 **지도의 노선 클릭** 또는 **목록의 노선 클릭** → 단일 노선 모드 (그 노선만 표시)
- 단일 모드에서 "Top5로 돌아가기" → Top5 모드 복귀
- 두 모드 모두 노선을 클릭하면 예측 상세 패널 표시

아직 정하지 않은 것: 목록 클릭 시 패널을 같이 열지, 단일 모드에서 빈 곳 클릭 시 동작

## 7. 데이터 메모 (저장소에는 없음)

- 노선 데이터는 BIS 공공데이터: 노선 `routeInfo`, 노선별 정류장 순서 `allRouteDetailInfo`, 정류장 좌표 `busStopInfo`
- 741.geojson을 만든 스크립트와 BIS 원본 CSV는 이 저장소가 아니라 **`D:\01-STUDY\dev\프로젝트\3p\py`** 폴더에 있습니다 (`make_route_geojson.py`, `data/bis_*.csv`). 다른 노선 파일이 더 필요하면 그 폴더를 집으로 가져가거나, 필요한 노선만 알려 달라고 요청하세요.
- 노선번호 하나에 방향이 두 개(예: 741 = 두 `BRTID`)라서 선도 방향마다 하나씩, 같은 색으로 그림
- 노선 키는 **BIS 노선번호(BRTNO)** 로 통일하고, 예측 쪽 노선 ID는 별도 매핑표로 연결할 계획
